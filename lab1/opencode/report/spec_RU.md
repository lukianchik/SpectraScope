# Спецификация: `POST /api/scans/preview`

Статус: это учебное описание. В лабораторной работе функция не реализовывалась.

## Какой запрос отправляет интерфейс

Используются те же основные поля, что и при запуске сканирования:

```json
{
  "target": "example.com",
  "scan_profile": "safe",
  "confirm_authorized": true
}
```

Пример разрешённого ответа:

```json
{
  "target": "example.com",
  "scan_profile": "safe",
  "decision": "allowed",
  "reason": null,
  "stages": ["discovery", "probing", "nuclei", "service_detection", "reporting"],
  "warnings": [],
  "side_effects": false
}
```

Поле `side_effects: false` означает, что предварительный просмотр ничего не запускал и не изменял.

## Что должна делать функция

1. Привести цель к нормальному виду и проверить её через `authorize_target`.
2. Проверить выбранный профиль через `validate_scan_profile_for_settings`.
3. Проверить область сети без DNS и других внешних запросов.
4. Построить список будущих этапов из профиля и настроек.
5. Использовать тот же список этапов при настоящем запуске, чтобы preview не обещал одно, а запускал другое.
6. Не обращаться к базе, очереди, сканерам и внешней сети.
7. Показать пользователю решение, этапы и предупреждения, оставив запуск отдельной кнопкой.

## Дополнительные требования

- Локальный ответ без внешнего I/O должен быть быстрым: p95 меньше 200 мс.
- Одинаковые входные данные должны давать одинаковый результат.
- Ответ не должен раскрывать секреты и внутренние команды сканеров.
- Неизвестный профиль и отсутствие подтверждения авторизации должны отклоняться.

## Как это проверять

- Разрешённая учебная цель возвращает план и не вызывает запуск Celery.
- Отсутствующее подтверждение, запрещённый домен и неподходящий профиль отклоняются.
- Профили `discovery`, `safe`, `lab` и `local-real` дают ожидаемые этапы.
- DNS, HTTP, subprocess, Celery и адаптеры сканеров не вызываются.
- Настоящий запуск использует тот же builder этапов, что и preview.

Специалист по безопасности должен подтвердить отсутствие внешних действий, а владелец API — согласовать контракт до начала реализации.
