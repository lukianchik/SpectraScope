# План: реализация безопасного preview

Это учебный план. В рамках лабораторной работы код по нему не создавался.

## Порядок работы

1. Сначала написать тесты, которые пока падают: отдельно для списка этапов и отдельно для API, отказов политики и отсутствия побочных действий.
2. Вынести построение этапов для каждого профиля в одну чистую функцию.
3. Перевести настоящий pipeline на эту функцию, чтобы preview и запуск использовали один источник истины.
4. Добавить схемы ответа preview и тип этапа.
5. Добавить `POST /preview`, используя уже существующие проверки цели, настроек и профиля.
6. Не вызывать в preview очистку старых запусков, запись в базу, commit или `run_scan.delay`.
7. Отделить чистую проверку сетевой политики от проверки, которая требует DNS.
8. Добавить кнопку Preview и отдельную кнопку Start в интерфейс.
9. Обновить документацию и выполнить все проверки.

## Команды проверки

```powershell
$env:PYTHONPATH = "backend"
pytest -q tests/test_scan_profiles.py tests/test_scan_lifecycle.py tests/test_target_policy.py tests/test_network_policy.py
pytest -q
bun run --cwd frontend lint
bun run --cwd frontend build
```

## Где совет, а где настоящее ограничение

Skill `spectrascope-review` напоминает агенту о проверке безопасности. Это только совет: текст можно проигнорировать.

Разрешения OpenCode требуют подтверждения правок и неизвестных команд, а также запрещают `git push` и удаление Docker volumes. Это уже ограничение действий агента.

Однако настоящая защита должна быть в коде и CI: тесты должны доказывать отсутствие сети, Celery и сканеров в preview. Командный hook также должен блокировать запуск реальных сканеров против неучебных целей.

## Переходы между этапами

- утверждённый замысел запускает подготовку спецификации;
- утверждённая спецификация запускает планирование;
- сначала фиксируются тесты и ожидаемое поведение;
- реализация допускается на review после успешных локальных проверок;
- независимый reviewer выносит вердикт;
- слияние выполняет человек.

## Как использовать нескольких агентов

Одной сессии достаточно для схем, документации и общей функции построения этапов. Отдельный свежий агент полезен для security-review отсутствия побочных действий. Frontend-агента имеет смысл подключать после того, как API уже согласован.

## Как отменить изменения

Функция не меняет структуру базы данных. При необходимости можно удалить маршрут preview и клиентский код, а pipeline вернуть к прежнему списку этапов. Существующий запуск сканирований при этом должен продолжить работать.
