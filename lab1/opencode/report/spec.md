# Spec: `POST /api/scans/preview`

Статус: учебная спецификация, реализация не входит в лабораторную работу №1.

## Контракт

Запрос переиспользует поля `ScanStartRequest`:

```json
{
  "target": "example.com",
  "scan_profile": "safe",
  "confirm_authorized": true
}
```

Успешный ответ `200 OK`:

```json
{
  "target": "example.com",
  "scan_profile": "safe",
  "decision": "allowed",
  "reason": null,
  "stages": ["discovery", "probing", "nuclei", "service_detection", "reporting"],
  "warnings": [],
  "side_effects": false
}
```

Ошибки target/profile/network policy используют тот же `ApiProblem` и код `TARGET_OR_PROFILE_INVALID`, что и запуск, пока продуктовый гейт не утвердит иную семантику.

## Функциональные требования

1. Нормализовать и авторизовать цель через `authorize_target`.
2. Проверить профиль через `validate_scan_profile_for_settings`.
3. Выполнить только статическую проверку сетевой области. Если текущая `validate_external_network_targets` делает DNS, для preview требуется отдельная чистая проверка конфигурации без резолвинга.
4. Построить стадии чистой функцией из профиля и настроек. Та же функция должна использоваться исполнительным pipeline, чтобы preview не расходился с запуском.
5. Не обращаться к БД, брокеру, scanner adapters или сети и не увеличивать `SCANS_STARTED_TOTAL`.
6. UI показывает решение, стадии и предупреждения, а запуск остаётся отдельным явным действием.

## Нефункциональные требования

- p95 ответа без внешнего I/O менее 200 мс на локальном стенде;
- одинаковые входы и настройки дают одинаковый порядок стадий;
- сообщение не раскрывает секреты и внутренние команды сканеров;
- неизвестный профиль и отсутствующее подтверждение авторизации отклоняются fail-closed.

## Приёмочные проверки

- Разрешённая mock-цель возвращает план и не вызывает `run_scan.delay`.
- Отсутствующее подтверждение, запрещённый домен и несовместимый профиль отклоняются.
- Профили `discovery`, `safe`, `lab`, `local-real` дают ожидаемые стадии.
- Моки DNS, HTTP, subprocess, Celery и scanner adapters остаются невызванными.
- Запуск с теми же входами использует тот же builder стадий.

## Гейт

Security reviewer утверждает доказательство отсутствия I/O; API owner утверждает контракт; после этого spec запускает создание `plan.md`.
