# Лабораторная работа №1: применение OpenCode в проекте SpectraScope

## 1. Цель работы

Цель работы — исследовать применение AI-агента OpenCode при разработке программного продукта, проверить способы постановки задач, настроить ограничения безопасности и сравнить облачную и локальную модели.

В качестве исходного материала использован репозиторий SpectraScope. В рамках лабораторной работы исследовался процесс разработки и подготовки решений. Новая функция `scan preview` в рабочий код проекта не добавлялась.

Исходная формулировка задания сохранена на [скриншоте](report/report_assets/00-assignment-page-9.png).

## 3. Подготовка OpenCode

OpenCode запускается из этой директории и автоматически читает следующие файлы:

| Файл | Назначение | Пояснение |
| --- | --- | --- |
| [`AGENTS.md`](AGENTS.md) | Рабочие правила агента | Архитектура проекта, команды, ограничения и требования безопасности |
| [`opencode.json`](opencode.json) | Конфигурация | Разрешения команд, подтверждение правок и локальный provider |
| [`SKILL.md`](.agents/skills/spectrascope-review/SKILL.md) | Специализированная проверка | Контроль авторизации целей, сетевой области, побочных действий и тестов |

Русские пояснения этих файлов: [AGENTS_RU.md](AGENTS_RU.md), [opencode_RU.md](opencode_RU.md) и [SKILL_RU.md](.agents/skills/spectrascope-review/SKILL_RU.md).

### Разрешения

В конфигурации:

- правки файлов требуют подтверждения;
- неизвестные команды требуют подтверждения;
- `git status`, `git diff`, `rg`, `pytest` и `bun run` разрешены для проверок;
- `git push` запрещён для агента;
- удаление Docker volumes запрещено;
- использование skills разрешено.

Такая схема оставляет AI возможность анализировать проект, но не даёт ему самостоятельно публиковать изменения или удалять данные.

### Команды запуска

```powershell
cd lab1/opencode
opencode
```

Установка и первый запуск:

```powershell
bun add --global opencode-ai
opencode --version
bunx opencode-ai run --model opencode/mimo-v2.6-flash-free "/init"
```

## 5. Эксперименты с постановкой задач

Сравнивались разные варианты инструкций для одной и той же модели и контекста.

| Приём | Наблюдение | Ограничение |
| --- | --- | --- |
| Извлечение фактов вместо общего резюме | Ответ содержит короткие проверяемые пункты и меньше интерпретаций | Не заменяет анализ при необходимости объяснить приоритеты |
| Формат `ФАКТ / ВЫВОД / ДОГАДКА` | Граница между подтверждёнными данными и предположениями становится явной | Увеличивает объём ответа |
| Уточняющие вопросы перед решением | Выявляются неясные требования, формат результата и ограничения | Не нужен при полностью определённой задаче |
| Самокритика первого ответа | Обнаруживаются пропущенные риски, тесты и архитектурные несоответствия | Рекомендации критика также требуют проверки |
| Явное отделение данных от инструкций | Модель лучше различает входной текст и команды | Это не заменяет permissions и изоляцию |

## 6. Проектирование безопасного preview

Для демонстрации AI-native SDLC выбран сценарий предварительного просмотра сканирования.

| Документ | Содержание |
| --- | --- |
| [`intent.md`](report/intent.md) | Цель, польза, участники, ограничения и вопросы для решения человеком |
| [`spec.md`](report/spec.md) | Контракт `POST /api/scans/preview`, требования, ошибки и приёмочные проверки |
| [`plan.md`](report/plan.md) | Порядок изменений, тесты, гейты, мультиагентность и откат |

Русские версии: [intent_RU.md](report/intent_RU.md), [spec_RU.md](report/spec_RU.md), [plan_RU.md](report/plan_RU.md).

Сценарий предполагает, что preview показывает нормализованную цель, решение политики, профиль, этапы и предупреждения, но не выполняет DNS, HTTP, subprocess, Celery или scanner I/O. Это проектный пример: endpoint и связанные изменения в SpectraScope не реализовывались.

## 7. Сравнение инструментов и моделей

### Зрелость агентных сред

Использовалась шкала из 33 баллов по признакам reasoning, autonomy, action, reflection, memory, role и domain knowledge.

| Среда | Результат | Основные наблюдения |
| --- | --- | --- |
| OpenCode | `26/33 = 78,8%` | Инструменты, permissions, skills, Build/Plan и subagents |
| Hermes | `30/33 = 90,9%` | Долговременная память, отдельные review/refine и делегирование |

### Оценка по отдельным критериям

Баллы выставлялись по шкале от 0 до 3, а вес показывал важность критерия. Максимум — 33 балла.

| Критерий | Вес | OpenCode | Hermes | Основание оценки |
| --- | ---: | ---: | ---: | --- |
| Reasoning — рассуждение | 3 | 2 | 2 | Обе среды умеют перестраивать решение по результатам инструментов |
| Autonomy — автономность | 3 | 2 | 2 | Рутинные действия выполняются самостоятельно, опасные требуют подтверждения |
| Action — действия | 2 | 3 | 3 | Есть shell, редактирование, web, skills, subagents и расширения |
| Reflection — самопроверка | 2 | 1 | 2 | В OpenCode review организуется вручную, в Hermes есть отдельные review/refine-команды |
| Memory — память | 2 | 1 | 2 | OpenCode использует сессии и проектные инструкции, Hermes имеет долговременную память |
| Role — роли | 1 | 2 | 2 | Есть режимы Build/Plan и специализированные агенты |
| Domain knowledge — знания проекта | 1 | 2 | 2 | Используются `AGENTS.md`, skills и проектные правила |
| **Итого** | **33** | **26** | **30** | **OpenCode: 26/33 = 78,8%; Hermes: 30/33 = 90,9%** |

Итоговый процент рассчитан как `набранные баллы / 33 * 100`. Hermes получил более высокий результат за счёт долговременной памяти и встроенного независимого review-процесса.

### Облачная и локальная модели

| Критерий | Облачная модель | Qwen2.5-Coder 1.5B локально |
| --- | --- | --- |
| Анализ кода | Лучше удерживает сложный контекст | Чаще ошибается на архитектурном review |
| Tool calling | Надёжнее вызывает инструменты | В эксперименте возвращала вызов как обычный текст |
| Приватность | Данные передаются провайдеру | Данные остаются на локальном компьютере |
| Стоимость | Зависит от провайдера и тарифа | Токеновая стоимость отсутствует |
| Подходящие задачи | Review, планирование, сложные вопросы | Черновики, классификация, извлечение фактов |

Команда локального запуска:

```powershell
llama-server.exe -m qwen2.5-coder-1.5b-instruct-q4_k_m.gguf `
  -c 16384 --host 127.0.0.1 --port 8080 `
  --alias qwen2.5-coder-1.5b --jinja

bunx opencode-ai run --model llama-cpp/qwen2.5-coder-1.5b `
  "Проведи ревью модуля target_policy.py"
```

Пути к бинарнику и модели зависят от компьютера.

## 9. Итог

В лабораторной работе показано, как использовать AI-агента в существующем проекте: подготовить контекст, задать правила, ограничить опасные действия, провести эксперименты, сравнить модели и проверить результат командами проекта.

Основной результат — воспроизводимый процесс и набор настроек, skill, экспериментов и отчётов. AI ускоряет изучение проекта и подготовку решений, но его выводы нельзя принимать без тестов и человеческой проверки. Текстовые инструкции помогают агенту, однако реальные границы безопасности должны обеспечиваться кодом, permissions, CI и ручным подтверждением.
