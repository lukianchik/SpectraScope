# Проверка изменений SpectraScope на русском

Это русское пояснение к рабочему skill [`SKILL.md`](SKILL.md). OpenCode автоматически использует только `SKILL.md`; файл `SKILL_RU.md` предназначен для человека.

## Что нужно сделать сначала

1. Прочитать `AGENTS.md`, `SECURITY.md` и изменённые файлы.
2. Посмотреть diff и ближайшие тесты.
3. Не смешивать найденные проблемы с посторонними изменениями.
4. Понять, затрагивает ли изменение API, правила целей, сеть, сканеры, авторизацию, секреты или базу данных.

## Что проверить

- Для запуска сканирования нужно явное подтверждение авторизации.
- Настоящие сканеры по умолчанию выключены и ограничены allowlist.
- Проверки цели, профиля и сети нельзя обходить.
- Preview и dry-run не должны выполнять DNS, HTTP, subprocess, Celery, сканеры или другой внешний I/O.
- Секреты, реальные цели, сырые результаты и дампы базы нельзя записывать в логи или коммитить.
- Ошибка не должна незаметно расширять область сканирования или превращаться в разрешение.
- Изменения API, базы и frontend должны оставаться совместимыми или меняться согласованно.

## Как проверять

Нужно начинать с самой маленькой подходящей проверки:

- для backend — с ближайшего тестового файла, потом запустить весь набор;
- для frontend — выполнить lint и build;
- для сканеров — проверить положительный и отрицательный варианты авторизации.

Нельзя запускать реальные сканеры против публичных или чужих целей. Используйте preview, моки или локальный учебный стенд.

## Как оформить результат

Сначала перечислите найденные проблемы по важности. Для каждой укажите файл, причину и короткий способ исправления. Отдельно отметьте проверенные дефекты, возможные риски, вопросы и тесты, которые не удалось выполнить.

Если проблем нет, так и напишите, но всё равно укажите оставшиеся риски и выполненные проверки.
