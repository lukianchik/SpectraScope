# Правила для AI-агента на русском

Это русское пояснение к рабочему файлу [`AGENTS.md`](AGENTS.md). OpenCode использует именно английский `AGENTS.md`; этот файл создан для удобного чтения человеком.

## Для чего нужен проект

SpectraScope помогает анализировать внешнюю поверхность систем: какие разрешённые сетевые сервисы доступны и какие проблемы безопасности можно обнаружить.

Работать можно только с целями, которыми владеет пользователь или на проверку которых у него есть явное разрешение.

## Что нельзя делать

- Нельзя отключать подтверждение авторизации цели.
- Нельзя ослаблять список разрешённых целей.
- Нельзя отключать сетевые ограничения.
- Нельзя включать настоящие сканеры по умолчанию.
- Нельзя добавлять пароли, токены и другие секреты.
- Нельзя добавлять реальные цели клиентов, сырые результаты сканирования или базы данных.
- Нельзя запускать проверки против публичных или чужих целей.

Уязвимый учебный стенд можно использовать только в доверенной локальной сети.

## Где находятся основные части проекта

- `backend/app/api` — HTTP-маршруты и обработка ошибок;
- `backend/app/services` — правила целей, сети, профили и запуск операций;
- `backend/app/scanners` — ограниченные адаптеры сканеров;
- `backend/app/workers` — фоновые задачи Celery;
- `backend/app/models` и `backend/app/schemas` — данные и API-контракты;
- `frontend/src` — интерфейс React и TypeScript;
- `tests` — автоматические тесты;
- `lab` — локальные учебные уязвимые сервисы.

Общий путь приложения выглядит так:

```text
React -> nginx -> FastAPI -> PostgreSQL
                         -> Redis -> Celery -> сканеры
```

## Как проверять изменения

Для backend сначала запускается ближайший подходящий тест, затем весь набор:

```powershell
$env:PYTHONPATH = "backend"
pytest -q
```

Для frontend запускаются:

```powershell
bun run --cwd frontend lint
bun run --cwd frontend build
```

Изменения сканеров и политики должны иметь тесты как для разрешённых, так и для запрещённых случаев.

## Главные правила разработки

- Маршруты FastAPI должны оставаться короткими; общие решения находятся в `backend/app/services`.
- Входные цели нужно проверять и приводить к нормальному виду до сохранения или запуска.
- Нужно использовать готовые проверки авторизации, профиля и сетевой области, а не обходить их.
- Режим preview или dry-run не должен обращаться к DNS, HTTP, subprocess, Celery, сканерам или внешней сети.
- Если политика или настройка недоступна, операция должна завершаться ошибкой, а не разрешаться автоматически.
- Нельзя без необходимости менять API-ответы, схемы базы и frontend-контракты.
- При изменении базы нужна миграция Alembic.
- Нельзя добавлять несвязанные форматирования и изменения зависимостей.

## Что проверить перед завершением

- Прошли нужные точечные тесты и полный backend-тестовый набор.
- Frontend прошёл lint и build.
- Для сканеров описано влияние на авторизацию и сетевую область.
- В коммит не попали секреты, реальные цели и посторонние файлы.
- В отчёте отмечены проверки, которые не удалось выполнить из-за отсутствия Docker или внешних сервисов.
