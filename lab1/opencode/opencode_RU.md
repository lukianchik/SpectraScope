# Конфигурация OpenCode простыми словами

Этот файл объясняет [`opencode.json`](opencode.json). Сам `opencode.json` должен оставаться JSON-файлом: OpenCode читает его автоматически, а этот документ предназначен для человека.

## Разрешения

В конфигурации есть раздел `permission`:

- `edit: ask` — перед изменением файла AI должен спросить разрешение;
- неизвестные команды в `bash` тоже требуют подтверждения;
- `git status`, `git diff`, `rg`, `pytest` и команды `bun run` разрешены для проверки;
- `git push` запрещён, чтобы AI не отправил изменения без контроля;
- `docker compose down -v` запрещён, потому что команда может удалить данные и тома;
- использование skills разрешено.

Идея простая: чтение и безопасные проверки можно выполнять быстрее, а изменения, удаление данных и публикация требуют контроля.

## Локальная модель

В конфигурации описан провайдер `llama-cpp`:

- модель: `Qwen2.5-Coder 1.5B Q4_K_M`;
- адрес локального сервера: `http://127.0.0.1:8080/v1`;
- максимальный контекст: 16 384 токена;
- максимальный ответ: 1 024 токена.

Это означает, что модель работает на собственном компьютере, а запросы к ней не отправляются внешнему сервису. Сначала нужно отдельно запустить `llama-server` с этой моделью.

Пример запуска сервера:

```powershell
llama-server.exe -m qwen2.5-coder-1.5b-instruct-q4_k_m.gguf `
  -c 16384 --host 127.0.0.1 --port 8080 `
  --alias qwen2.5-coder-1.5b --jinja
```

После этого OpenCode может использовать локальную модель через провайдера `llama-cpp`.

## Важно

Русское описание не заменяет рабочий JSON и не должно переименовываться в `opencode.json`. Если изменить настоящий JSON неправильным текстом, OpenCode не сможет его прочитать.
